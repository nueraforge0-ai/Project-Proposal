### 1.10 Conceptual Model

**Found-item flow:** Finder → hands item to Security at the main gate → Security Officer registers the item (category, description, photographs, date and time received, storage location) → Found-item register (public view shows category and general description only) → Owner searches, or receives a match suggestion → Owner submits a claim with identifying details → Officer verifies → Release recorded as Returned, or marked Unclaimed after the retention period.

**Lost-item flow:** Owner → submits a lost-item report (description, place, time, optional photographs) → System compares the report with the found-item register → AI match suggestions for the Security Officer → Owner notified of a possible match after the officer has reviewed it → Claim, verification and release.

**Analytics flow:** Database → Aggregation and anonymisation → AI summary → Review by Security Officer or Administrator → Dashboard and downloadable report.

The inputs are found-item records, lost-item reports and claims. The system processes them through authentication, validation, secure storage, role-based access, matching and claim management. The outputs are searchable records, status updates, match suggestions, notifications, summaries and reports for authorised users.
