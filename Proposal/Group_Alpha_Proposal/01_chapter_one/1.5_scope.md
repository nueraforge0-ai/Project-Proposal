### 1.5 Scope of the Study

#### 1.5.1 Content Scope

The study focuses on lost and found property within or directly associated with Nkumba University's main campus. Typical items are phones, laptops, identity cards, keys, books, chargers, flash disks and bags. Security officers register each found item at the main gate with a category, description, photographs, the date and time received, where it was found and where it is stored. Users report lost items with a description, the place and time of loss and optional photographs, and search the register of found items. A claim is verified by Security before release, and every release is recorded. Items still unclaimed after a retention period set by the university are marked as unclaimed so that Security can decide what to do with them **[CONFIRM: retention period]**.

The system has three user roles. Student or Staff Users report lost items, search found items, submit claims and track their status. Security Officers register found items, review claims, release items and update statuses. Administrators, from the ICT Directorate **[CONFIRM: exact office name]**, manage accounts and view summaries and reports. Visitors without a university account can ask a Security Officer at the gate to search on their behalf **[CONFIRM]**. The system does not handle theft reports, does not identify or accuse any person, and does not replace Security procedures or police investigation.

#### 1.5.2 Geographical Scope

The study is conducted at Nkumba University's main campus on Nkumba Hill, Wakiso District, along the Kampala-Entebbe Highway (Nkumba University, n.d.), with the main gate as the point where found items are received. Testing may include selected student hostels where Wi-Fi is available.

#### 1.5.3 Population Scope

The study population comprises Nkumba University students, members of the University Security Unit and relevant ICT Directorate staff, with particular reference to the School of Computing and Informatics. Because the study cannot reach all of these groups within the available time and resources, the accessible population is limited accordingly. The sample is described in Chapter Three.

#### 1.5.4 Technical Scope

The project covers requirements analysis, interface and database design, development of a responsive web application with progressive web application features (React for the front end, Express for the server and MySQL for the database), authentication, role-based access control (RBAC) (Rangappa, 2023), photograph upload, found-item registration, lost-item reporting, search, claim verification and release, notifications, an AI module, report export in PDF and CSV, testing and evaluation. Development follows an iterative software engineering process (Anifa et al., 2024). Common web application risks will be checked against the OWASP Top 10 (OWASP Foundation, 2021).

The AI module runs on the server, and any API key is never exposed to the browser. It suggests matches between lost reports and found items using category, description, colour, place and date, with photographs used to help officers confirm a match, suggests a category for a newly registered item, and writes short summaries of trends. Counts and statistics are calculated by database queries, and AI is used only to explain and summarise them. Names, contacts and identity numbers are removed before any data is sent to an external AI service. All AI output is labelled as AI-generated and reviewed by authorised staff.

#### 1.5.5 Ethical and Security Scope

Access is restricted by role. A user sees only their own reports and claims. Public listings show only a category and a general description, and identifying details such as names and identity numbers are withheld and used only for verification at release. Identity cards and similar items are treated as sensitive. The project applies purpose limitation, data minimisation, controlled access and defined retention in line with the Data Protection and Privacy Act, 2019 (Uganda, 2019), and uses Privacy by Design (International Organization for Standardization, 2023) as guidance. AI summaries are visible only to Security Officers and Administrators. Exports used for research contain anonymised, aggregated data only.

#### 1.5.6 Priority of Features

To keep the scope achievable within the available time, found-item registration, lost-item reporting, search, claim verification and release, and role-based access are the core features. AI-assisted matching, category suggestion, trend summaries and report export are enhancements built on the core. Photograph-based matching is attempted only after text-based matching works.
