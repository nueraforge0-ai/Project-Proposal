### 2.6 Empirical Review

The reviewed studies follow a similar path from a manual or informal process to a searchable digital record. Tan and Chong (2023) started with a pretest survey of 50 students and staff, built FoundeLost, and evaluated it with 20 testers using a 24-item questionnaire on usability, ease of use, ease of learning and satisfaction. Testers were satisfied overall. They asked for pop-up notifications, for guidance for first-time users, and for non-registered users to be able to search the list. The authors name user engagement, security and Android-only access as limitations, and list data analytics, integration with campus security and machine-learning matching as future work.

Murugiah and Mat Nawi (2025) followed an Agile approach to build FindItHere, with registration, reporting and notification features developed in phases. Ngu (2025) used the waterfall model, collected user feedback through Google Forms to identify the problems of informal channels, and tested FindIt for function and usability. Twayigize (2025) used prototyping to build an AI-driven system at Strathmore University around CLIP image-text matching. Itaagi (2022) surveyed Makerere University students before developing a mobile application for finding lost items.

The common pattern is that each study begins with user data, builds a prototype in iterations, and evaluates it with a small group of users. This project follows the same pattern, adapted to a setting where the Security Unit holds the items.
