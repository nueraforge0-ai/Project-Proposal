### 3.13 Work Plan

The plan below is counted in weeks from the approval of the proposal **[CONFIRM: start date and number of weeks available]**. Each phase has a lead, but all five members take part in every phase.

| **Phase** | **Main activities** | **Weeks** | **Lead** |
|----|----|----|----|
| Requirements analysis | Questionnaire, interviews, observation at the main gate, document review, requirements specification | 1-2 | Precious (analyst) |
| System design | Use case, activity and data flow diagrams, database design, interface designs, access rules, AI module design | 3-4 | Precious (analyst), Innocent (developer) |
| Core implementation | Authentication, role-based access, found-item register, lost reports, search, claims and release | 4-8 | Innocent (developer), Derrick (programmer) |
| AI and PWA features | Match suggestion, category suggestion, trend summaries, PWA features | 7-9 | Derrick (programmer), Innocent (developer) |
| Testing | Functional, security, AI matching and compatibility tests; fault correction | 9-10 | Owen (tester) |
| Evaluation | User testing, SUS and TAM/UTAUT questionnaire, follow-up discussions | 10-11 | Owen (tester), Precious (analyst) |
| Analysis and report writing | Data analysis, final report and presentation | 9-12 | Fred (writer) |

The core functions are finished before the AI features begin, in line with the priority of features in Section 1.5.6.
