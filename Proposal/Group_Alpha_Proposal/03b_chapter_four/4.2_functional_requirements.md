### 4.2 Preliminary Functional Requirements

| **ID** | **Requirement** | **Role** |
|----|----|----|
| FR1 | Register and log in with university details | User, Officer, Administrator |
| FR2 | Register a found item with category, description, photographs, date and time received and storage location | Security Officer |
| FR3 | Report a lost item with description, place, time and optional photographs | User |
| FR4 | Search the found-item register (public view shows category and general description only) | User |
| FR5 | Submit a claim with identifying details that support ownership | User |
| FR6 | Verify a claim and record the release of the item | Security Officer |
| FR7 | Mark items still unclaimed after the retention period | Security Officer, system |
| FR8 | Show ranked match suggestions for a lost report, for officer review | Security Officer |
| FR9 | Suggest a category and key details when a found item is registered | Security Officer |
| FR10 | Send notifications and show claim status | User |
| FR11 | Manage accounts and roles | Administrator |
| FR12 | Show a dashboard with AI trend summaries and exact figures from the database | Administrator, Security Officer |
| FR13 | Export anonymised PDF and CSV reports | Administrator |
| FR14 | Keep a log of claims, releases and access to stored photographs | Administrator |

Match suggestions are shown first to the officer. An owner is told about a possible match only after an officer has reviewed it, so that details of a held item are not shown to the wrong person.
