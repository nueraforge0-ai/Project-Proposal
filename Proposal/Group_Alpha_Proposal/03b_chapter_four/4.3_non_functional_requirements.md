### 4.3 Preliminary Non-Functional Requirements

The non-functional requirements are organised using the quality characteristics of ISO/IEC 25010 (International Organization for Standardization, 2011).

| **Quality** | **Requirement** |
|----|----|
| Security | Authentication, role-based access, salted password hashes, validated input, prepared statements, checked uploads, photographs stored outside public folders |
| Privacy | Data minimisation, no names, contacts or identity numbers sent to an AI service, defined retention, in line with Uganda (2019) |
| Usability | Simple forms that work on small screens; first-time user guidance; measured with the System Usability Scale |
| Performance | Lightweight pages and compressed photographs so the system remains usable on mobile data |
| Reliability | Correct handling of errors and poor connectivity; no data loss during normal use |
| Compatibility | Works in common modern browsers on smartphones and computers, and can be installed as a PWA |
| Maintainability | Modular code, version control and documented interfaces |
